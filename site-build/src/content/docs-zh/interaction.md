# 互動流程與回饋

設計的單位是完整互動歷程，不只是操作畫面。

## 基本流程，分支出正式設計

**未使用／純鏡面 → 注意到系統 → 理解可做什麼 → 開始參與 → 操作與回饋 → 完成或退出 → 重設。**

以下分支當成正式設計，而不是工程例外：追蹤中斷、辨識不確定、誤觸、使用者離開、第二人加入、切換使用者、網路或設備失敗。

```rule
id: FLOW-01
title: 每條流程都要處理四組區分：注意到、偵測到、追蹤到、離開
normative: should
evidence: decision
tech: both
scope: 所有互動鏡面歷程。
statement: 注意到不等於想操作；偵測到不等於已選取；追蹤不到不等於換下一個人；離開不等於流程已妥善結束。每組配不同回饋與不同恢復路徑。
why: 壓扁這些狀態就是鏡面經典故障：拍下路人、搶走工作階段、把下一位丟在別人的狀態裡。
wrong: 靠近就開始拍攝儲存；追蹤一斷就把工作階段交給旁邊的人。
fix: 注意到只給低風險回應（「這裡可以互動」），不含同意意涵；偵測、指向、完成各有不同回饋；追蹤中斷暫停提交並顯示恢復方式；離開觸發明確取消、資料清除與下一位重設。
verify: 帶真實使用者走完四組轉換；記下設計叫不出名字的每個狀態——每個無名狀態都是缺失的設計。
gaps: 時間閾值（一瞥與注視的界線）因場景而異；各部署自行記錄，不全球凍結。
```

## 拍攝前先取得同意

```rule
id: PRIV-01
title: 拍攝、儲存或公開個人內容前取得明確確認
normative: must
evidence: decision
tech: both
scope: 任何可識別個人內容的拍攝、儲存或分享。
statement: 靠近、注視或路過絕不等於同意拍攝、儲存或公開。拍攝需要明確、可撤回的確認步驟。
why: 鏡子邀請身體，身體不是同意書。團隊把這條訂為必須，並老實標為團隊決策——不假裝是某篇實驗推導出的唯一解。
wrong: 「站在這裡試穿」順手把照片存下來「改善服務」。
fix: 試用與儲存分開兩步；說明保留什麼、留多久、怎麼刪；未確認就離開預設刪除。
verify: 每次部署做隱私走查：列出每個儲存位元組、理由、期限、刪除路徑。
gaps: 各地法規疊加在本條之上；團隊須自行對應管轄區。
```

## 不預設輸入方式

觸控有明確接觸位置，但要付出伸手距離與清潔成本；手勢免接觸，但要處理發現、辨識與回饋。不要指定所有鏡子用同一種方式。

```rule
id: INP-01
title: 按任務條件選擇輸入方式，每種都要有具名替代
normative: should
evidence: cross-domain
tech: both
scope: 鏡面上的觸控、手勢、語音、實體控制與手機輔助。
statement: 每種方式寫下：適合什麼任務、需要什麼環境、失敗時用什麼替代。量測持續與重複懸空操作的身體負擔，不只測辨識率。
why: 每種方式的失敗模式不同——距離與指紋、發現與漂移、噪音與隱私；一種方式覆蓋不了所有任務。
wrong: 「手勢最自然」就是全部輸入策略，辨識失敗與手痠都沒有答案。
fix: 每個專案發布選擇表；每個主要方式具名替代；持續舉手操作安排休息或混合輸入。
verify: 每種方式下測任務完成，外加失敗注入（手被遮、環境吵、濕手）；記錄替代被使用的次數，不只記主要成功率。
gaps: 各手勢詞彙的疲勞預算待量測；先把主觀費力感與任務時間一起記錄。
```
