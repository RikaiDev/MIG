# 資訊與版面設計

背景不是設計師選的，版面決策必須從任務需要的倒影開始，而不是從螢幕柵格開始。

## 任務倒影區域，而非固定安全區

以下是建議的情境化設計方式，不是固定安全區的研究數值：

```rule
id: ZONE-01
title: 先定義任務所需的倒影區域，再放資訊
normative: should
evidence: decision
tech: both
scope: 所有含人物身體任務的鏡面內容。
statement: 每個任務先寫下必須保留的倒影資訊，再決定資訊位置；UI 放四角雖避開身體，卻未必看得清楚、摸得到——保留倒影、資訊可讀、操作可及三者一起考量。
why: 同一份 UI 背後可能是白衣、深色衣服、花紋、窗戶或另一個人；固定留白區無法覆蓋這些變化。
wrong: 全站統一中間留空、四角放資訊，結果試衣任務中衣服被價格標籤遮住。
fix: 按下表定義各任務的保留區與禁區；資訊避開保留區，操作目標放在可及範圍。
verify: 找三位不同身高、不同衣著的使用者執行任務，全程錄影檢查保留區是否曾被遮擋。
gaps: 各任務保留區的量化尺寸需實測累積；第一版只給方向，不給公分數。
```

| 任務 | 應優先保留的倒影資訊 | 設計上要避免 |
|---|---|---|
| 梳妝、整理儀容 | 臉部與正在操作的局部 | 提示或選單一直遮住正在檢查的地方 |
| 試衣、穿搭 | 服裝輪廓、身體比例、轉身比較 | 大面積介面遮住真正要評估的衣服 |
| 動作引導 | 身體姿態、關節與動作範圍 | 裝飾動畫與指導標記混在一起難區分 |
| 展覽、娛樂 | 與體驗相關的身體或倒影區域 | 效果很多，卻不知哪個變化是自己造成的 |

## 左右參照用身體，不用畫面座標

```rule
id: POS-02
title: 方向指示用使用者的身體參照，不整面翻轉 UI
normative: should
evidence: cross-domain
tech: both
scope: 含左右方向指示的動作引導與試衣內容。
statement: 「抬左手」指使用者的身體左側；用身體參照設計指示，不得把整個 UI 與文字一起翻轉了事。
why: 鏡像本來就反轉，畫面座標的左右與使用者感知的左右必然衝突；整面翻轉會連文字一起鏡像，無法閱讀。
wrong: 為了對齊倒影把整個介面鏡像翻轉，中文說明變成反字。
fix: 方向箭頭以使用者視角繪製；文字永遠正向；必要時用「你的左手」而非「左邊」。
verify: 請使用者依指示舉手，記錄左右錯誤率；錯誤率高於偶然即 redesign。
gaps: 兒童與高齡者對身體參照詞的理解差異尚未測試。
```

## 字體與目標：記錄物理條件，不只給 px

字體及目標大小應同時記錄實體尺寸、觀看距離與測試條件。沒有硬體與情境資料時，不直接寫死「字體至少多少 px」——應記錄適用設備、距離、照明、族群、任務與測試結果。
