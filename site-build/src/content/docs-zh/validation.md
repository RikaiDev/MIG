# 驗證與部署

```rule
id: VAL-01
title: 在現場簽核，不在設計稿上簽核
normative: should
evidence: decision
tech: both
scope: 每次鏡面上線前，以及任何硬體、燈光、擺位變更後。
statement: 驗收必須跑完檢查清單頁的光學測試、環境矩陣、現場驗收表——全部在已安裝的機器上跑，並記錄條件。
why: 設計稿重現不了疊加亮度、鏡後深度與感測品質；在工作室簽核等於簽了另一台機器。
wrong: Figma 過了就上線；現場沒人看得懂也沒人會開始。
do: 上線門檻就是三張表，在已安裝機器上跑完。
fix: 上線門檻就是三張表；任何物理變更後重跑受影響子集。
impl: 物理變更後重跑子集；沒簽表上線是流程失效。
verify: 表本身就是驗證；沒填完表就上線是流程失效，不是設計品味問題。
gaps: 跨場地的結果可比性需要共用回報模板——檢查清單頁是第一版草稿。
```

## 兩種驗證

**驗證鏡面設計**：在指定照明、背景、距離與使用者條件下，量測辨讀、誤操作、任務完成、恢復與身體負擔；公共情境還要測試「沒有人解說時，能否自行開始」。

**驗證 guideline 網站**：給設計者一個真實問題，觀察他能否找到規則、判斷是否適用、選出合理做法，並說出如何驗證。看了幾頁不是成功指標。
