# Research basis and versioning

Borrow methods, not parameters. None of the studies below are mirror-device specs; each row states what it contributes and where its boundary lies.

| Study | What it contributes to this guide | Boundary |
|---|---|---|
| **Looking Glass, CHI 2012** | Real-time response to passersby conveys interactivity (attract loops, start pattern) | Video-based public displays, not optical half-mirror specs |
| **Proxemic Interactions, 2011** | Distance/orientation/movement/multi-person scaffold for approach–engage–leave | A framework, not proof that any fixed distance means consent |
| **Consumed Endurance, CHI 2014** | Measure sustained and repeated mid-air load via arm biomechanics | Cross-domain evidence for mirrors, not direct mirror research |
| **AR Fitting-Room Patterns, 2022** | Nine interaction patterns from systems plus literature; lends the problem–context–solution–example structure | Retail try-on context; focus-group support is not large-scale validation |
| **3D-Mirrorcle, 2024 author version** | Names depth/position mismatch of reflection vs content as the core problem, with prototype and user-study validation | Specific stereoscopic setup; plain-screen software alone cannot claim the same effect |
| **Reverse Vampire UI, CHI EA 2025** | Operating behind-mirror UI with the reflected hand; the interaction plane itself is a variable | 12-person pilot; authors state no general conclusions; comparison conditions differ in hardware |

A transplant warning worth stating plainly:

> **An ordinary mirror's reflection already follows you, so "it follows me" alone never proves interactivity.**

Porting Looking Glass to real mirrors must test *recognizable digital response* — a cue with clear causality to the hand — not assume seeing oneself teaches operation.

## Method references (how-to, not specs)

| Source | What we borrow | What we do not copy |
|---|---|---|
| **Ultraleap TouchFree guidelines** | Show behavior animated (Guidance; Hover States); attract → guide → teach as designed work | Touchless-screen parameters; mirror optics still separate |
| **Microsoft Mixed Reality: Comfort** | Limit → why → how to avoid → what to test, turning body/hardware limits into rules | Headset distances, angles, depth numbers as mirror specs |
| **GOV.UK Design System patterns** | Task-named pages; when-to-use → how-it-works → research → known gaps | Their domain content |
| **IBM Carbon** | Single-page organization (usage / demo / spec / verification); do–don't with handoff | A component library as the star; patterns lead here |
| **Japan Digital Agency design system (typography)** | Noto family pairing, 170% CJK body line-height, 140% headings, links never color-only, 14px floor | JP-government context; our serif pairing and warm tokens are our own decision |

## Versions

Semantic. Minor = new proposed rules. Major = a validation graduates or revokes a rule. Tools must record which MIG version they cite. Current: v0.1.0 draft, provisional, not ratified.
